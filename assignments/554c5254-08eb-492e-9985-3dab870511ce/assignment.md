# 作业一：待办事项 API

## 任务

使用 FastAPI 实现一个内存版待办事项 API，并用 pytest 为接口编写自动化测试。数据可以保存在字典中，不要求连接数据库。

请先阅读以下讲义，再完成本作业：

- `materials/01-http-rest.md`
- `materials/02-fastapi.md`
- `materials/03-pytest-api.md`

## 接口要求

接口根资源为 `/todos`。待办事项包含 `id`、`title`、`completed` 三个字段：

- `id`：正整数，创建时由服务端生成并递增。
- `title`：字符串，去除首尾空白后长度必须为 1～200。
- `completed`：布尔值，创建时默认为 `false`。

必须实现以下接口：

| 方法 | 路径 | 说明 | 成功状态码 |
| --- | --- | --- | --- |
| `GET` | `/health` | 健康检查，返回 `{"status": "ok"}` | `200` |
| `GET` | `/todos` | 返回全部待办事项，按 `id` 升序排列 | `200` |
| `POST` | `/todos` | 新建待办事项，请求体至少包含 `title` | `201` |
| `GET` | `/todos/{todo_id}` | 查询单个待办事项 | `200` |
| `PATCH` | `/todos/{todo_id}` | 修改 `title` 和/或 `completed` | `200` |
| `DELETE` | `/todos/{todo_id}` | 删除待办事项 | `204` |

接口约定：

1. 新建和查询成功时返回完整对象，例如：

   ```json
   {"id": 1, "title": "完成接口测试", "completed": false}
   ```

2. `PATCH` 只修改请求体中出现的字段，未出现的字段保持原值。
3. 标题为空、标题超过 200 个字符或字段类型错误时返回 `422`。
4. 查询、修改或删除不存在的 `todo_id` 时返回 `404`。
5. 删除成功后响应体为空；再次查询该 ID 应返回 `404`。
6. 所有响应使用 JSON；`204` 除外。

## pytest 测试要求

至少编写 **5 个独立的 `test_` 测试函数**，使用 `pytest` 和 FastAPI 的 `TestClient` 调用真实接口。不能只调用路由函数，也不能把全部断言塞进一个测试。

全部测试必须满足：

- 至少覆盖创建成功，以及一次创建后的读取或状态验证。
- 至少覆盖一次 `422` 参数校验失败。
- 至少覆盖一次 `404` 资源不存在。
- 至少验证一次会改变数据的操作，例如 `PATCH` 或 `DELETE`。
- 测试之间相互隔离，不能依赖执行顺序或上一个测试留下的数据。
- 允许使用 fixture 清空内存数据；如果使用全局字典，必须在每个测试前重置。

建议覆盖的场景包括：健康检查、创建、列表、单条查询、非法标题、缺少资源、部分更新、删除后确认不存在。参数化测试算一个测试函数，但应包含多组有意义的输入。
